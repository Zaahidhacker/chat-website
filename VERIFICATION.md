## What the browser tests cover

`npm run test:browser` runs the real UI and Supabase SDK in two isolated Chromium contexts against a clearly labeled, test-only HTTP/WebSocket fixture. It covers messages both ways, receipts, edits, reactions, lost acknowledgements with duplicate-free retry, 120 missed messages and offline edits, bounded history, reading older history, personal clear isolation, Keepsakes, reload-safe retry, sign-out and phone performance.

`npm run test:upgrades` adds:

1. A closed mobile sidebar has no overlay shadow, is invisible and cannot intercept touches.
2. Swipe right creates the correct reply; vertical scroll and cancellation do not.
3. Actual Chromium touch input exercises capture transfer and swipe reply (not only synthetic DOM events).
4. An original message outside the current history page is fetched for the quote; hiding it removes the cached quote too.
5. Persisted sessions survive a new browser context and expired-token refresh.
6. A transport failure during restoration preserves the session and reconnects without a password.
7. Dark/light layouts at 320, 360, 390, 768 and 1440 pixels stay within the viewport. A shortened 420-pixel phone viewport keeps the composer visible.
8. Reduced-motion preferences disable gesture transitions; arrival effects also check the preference.
9. The actual built service-worker handlers use real IndexedDB, reject the wrong recipient and signed-out state, and generate generic notification text. The browser's notification display API is stubbed for this deterministic check; this does not prove delivery by Apple, Google or Mozilla.

## Live backend checks

`tests/push-database.sql` can run safely against this in-use project. It rolls back only its own subscription and delivery-claim fixtures. It verifies own-device management, partner isolation, nonmember denial, rejection of arbitrary push hosts, private signing-key ACLs, anonymous registration denial and duplicate-delivery claims. It does not change historic conversations.

The deployed `universe-push` handler was checked through the configured database networking service:

- Invalid webhook secret → **401 Unauthorized**.
- Valid webhook secret with an invalid message identifier → **400 Invalid message**.
- Valid webhook secret and an existing message with no registered devices → **200, sent: 0**. No user notification was generated by this test.

The notification tables have RLS. Private configuration/delivery tables intentionally have no client policies. Security advisors report the expected authenticated security-definer RPCs for manual review, plus Supabase's existing disabled leaked-password protection setting. There are no anonymous chat or push registration RPCs, and server signing material is not executable/readable by app accounts.

The original `tests/database.sql` passed before launch. It **refuses to run on an in-use conversation** and was not rerun or weakened during this upgrade.

## Limits

The user independently confirmed real enrollment and two-way messaging. This workspace still blocks direct automated browser access to the live Supabase and Vercel origins, so the browser integration transport remains a fixture. Native Vercel tools verify production HTML/assets and deployment status separately.

Physical Android/iPhone delivery, closed-app push arrival through each vendor, Safari touch behavior, real-device battery use and the exact cause of the earlier intermittent “Failed to fetch” cannot be fully verified here. Push permission must be enabled on each device. Free-tier cold starts, browser storage clearing, provider limits and network outages remain outside the app's control. No fixed delivery time or zero-lag guarantee is made.
