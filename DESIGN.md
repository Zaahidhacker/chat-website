# Our Little Universe — interface design

## Taste v2 refresh — November 4–5, 2026 (Asia/Colombo)

Installed the current `Leonxlnx/taste-skill` with its official skills CLI for Codex. The current upstream package provides **one skill**, `design-taste-frontend` (Taste v2), with a complete app-screen workflow. Its inventory, direction draw, shell rules, state review, motion guidance, source lint, browser inspector and written critique were used. The skill is in the workspace's ignored `.agents/skills/design-taste-frontend`; `skills-lock.json` records its upstream path/hash. A fresh checkout can restore it with `npx skills add Leonxlnx/taste-skill --skill design-taste-frontend --agent codex --yes`.

The selected direction is **True-black flat, seed 228952818**: warm near-black surfaces, elevation by lightness, quiet rules and neutral navigation. The shell was redrawn once from No sidebar to **Ruled T-frame** because the app has seven established destinations. Baby-pink outgoing messages and send control are intentional brand adaptations requested by the owner. Poppins is the app face; Caveat is reserved for the handwritten personal note/history greeting. The existing serif wordmark remains on sign-in. No UI framework, animation library or production dependency was added.

The chat's question is “What did my person say, and how can I reply?” Messages own the canvas, with a 240px labelled sidebar, a useful 64px desktop header, an 860px conversation lane and equal gutters. At tablet widths the sidebar becomes 224px; phones get a drawer and five labelled bottom destinations. Short phone viewports prioritize messaging, with all destinations still in the menu. Settings asks “What can I personalize and control?” and uses real-purpose sections with a label column. World asks “What can we do together?” and keeps all existing destinations, games and romantic activities.

Replies have explicit inset spacing, readable names and bounded quotes. Mobile message text is 15px; editable mobile fields are 16px. Composer controls have 44px height, and the send target is 44px square. On the narrowest phones, emoji selection remains available in Conversation options. Voice notes have a distinct play affordance and truthful expiry copy. Theme choices expose selection to assistive technology. Mobile navigation traps keyboard focus, makes the conversation inert while open, restores focus on dismissal and releases its state on desktop resize. Opening a note dismisses the sheet first. Restored, inserted and edited drafts resize immediately; one width-sensitive observer handles reflow and disconnects on navigation/sign-out.

Motion provides press, focus, hover, receipt and dialog feedback. It does not replay an entrance on every message or navigation. There is no new polling, rendering loop, remote font, paid API or always-running effect. Existing meaningful game/romantic animations remain; reduced motion and background pausing stay supported.

Browser review used the skill's inspector against built assets at 1440/768/390, plus functional layouts at 320/360/390/768/1440 and compact keyboard heights. A local-only sample route enabled the inspector without exposing accounts or adding a production route. All sample names/messages come from the existing explicitly fictional preview or isolated `@test.invalid` transport fixture. Production continues to use the actual accounts and stored content; no sample data is injected into production.

Documented check allowances: message emojis and the existing personal blossom/heart brand are semantic content, not dashboard decoration. The immutable voice-note body marker is retained for compatibility. The chat inspector's covered-text observation is the beginning-of-history greeting naturally outside the native message scroll viewport when anchored at the latest message; scrolling to the top reveals it. This exemption does not apply to real overlays or dialog collisions. App navigation/category labels are permitted by the app workflow, despite the general source “eyebrow” warning. Shadows are restricted to real floating composer/dialog/drawer surfaces; the composer explicitly disables backdrop filtering. Controls may have stronger selected/focus outlines than structural rules.

No database migration, account change, message rewrite, media operation or game-progress change was needed. All new verification uses synthetic accounts and transport. Browser/device emulation does not establish physical iPhone/Android or live Supabase radio-network behavior. Existing foreground-presence logic is preserved: visible chat, settings and games stay Online; leaving the website withdraws presence, while a lost network/force-killed browser waits for disconnect detection.

## Reliability and readability polish — November 3, 2026

The supplied baby-pink/Poppins/Caveat design and existing navigation remain. Voice dialogs now have a distinct heart mark, a readable recording clock, native playback, size/duration details and a clear re-record/send hierarchy. The clock is hidden from the accessibility tree so its one-second updates do not repeatedly announce over the recording instructions. Mobile inputs use 16px text to avoid iOS focus zoom. Light-theme sidebar labels and phone message actions have stronger contrast; dialogs use their visible heading as an accessible name and keep native media controls in the keyboard focus sequence.

Search operates on loaded messages without extra database requests. Its compact result cards show author and time, safely highlight matching text, keep long messages to contextual snippets, and return to the chosen message with a temporary outline. Closed or superseded lazy-loaded dialogs cannot reopen after a slow import finishes. Existing games, personal content, reply spacing and reduced-motion behavior are preserved.

Signed-in icon paths now load with the conversation; the public login retains only the two paths it can need before sign-in. All 24 original paths are unchanged. Initial JavaScript and CSS total 24,128 bytes gzip under the unchanged 25,000-byte guard. The new axe-core dependency is a development-only accessibility test tool and is not bundled into the site.

## Verification for the Taste refresh

`npm test` passes 63 unit tests. The new `npm run test:taste` exercises narrow-phone emoji access, keyboard trapping/restoration, note dialogs opened from navigation, phone-to-desktop resize, restored multiline drafts, and theme selection without changing messages/keepsakes. It is included in the existing GitHub verification workflow. The earlier overhaul test now checks the current foreground-presence contract: an old database heartbeat cannot make a visible partner appear offline.

The unchanged entry budget is **25,000 bytes gzip**; this build is **23,943 bytes**. The two-client browser performance check measured a roughly two-second cold login under 6× CPU throttling, 150ms latency and 1.6Mbps bandwidth; measurements depend on hardware. Accessibility checks found zero violations across twelve login/chat/search/audio/settings/retry states in both themes. Existing media, location, game, heart-secret, anniversary, transport, offline-retry and presence suites were exercised using deterministic transport. The skill's final chat and settings inspectors reported no findings at 1440/768/390; the phone World copy was increased after its final screenshot review. Long-lived desktop/phone sessions also exercise background return, reloads, offline retries and bounded history; reports remain in ignored `work/` rather than shipping test data.

The slower hosted runner caught the first sign-in build at 4.35 seconds against the unchanged 4-second cold-login gate. Twenty-five leftover blur, backdrop-filter and glow/shadow utility classes were removed from sign-in, preserving its layout and the small transform/opacity orbit animation. Five local cold runs before and after measured medians of 2.387s and 2.143s under 6× CPU/150ms/1.6Mbps emulation; these are a local comparison, not a physical-phone guarantee. The unchanged browser test now prints its resource timings so future failures are diagnosable.

The final real-state walkthrough also found that changing appearance rebuilt the message log at its initial position. Theme changes now retain either the latest-message position or the earlier reading offset, along with the draft, and ignore completions after sign-out/session changes. The new browser regression checks both positions. Reply, recorded voice-note preview/bubble, empty conversation and offline retry states also passed the additional settled-state accessibility review in both themes.

New-message feedback keeps text fully opaque while using a short transform-only movement. This preserves readable contrast during arrival and when an offline send exposes its retry control. Failed-send accessibility checks now run in both themes as part of the regular suite.
